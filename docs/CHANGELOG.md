## Known conflicts recorded (spec wins; code still to be changed in S0)
- Port: starter 3000 → spec 8080.
- Error body: starter `{error_code,message,details[]}` → spec `{error:{code,message,details:{}}}`; `INVALID_JSON` → `VALIDATION_ERROR`.
- `/health` body: starter `{"status":"ok","db":…,"cache":…}` → spec `{"status":"ok"}`.
- Timestamps: starter `.000Z` → spec `YYYY-MM-DDTHH:MM:SSZ`.
- Mobile storage: starter AsyncStorage suggestion → spec SQLite/Room/Hive + Keystore.
- `.gitignore` ignores `*.apk` → spec requires `mobile/release/app-release.apk` committed.
- Test runner: starter `scripts/run-tests.sh` → spec root `run_tests.sh` + `COVERAGE.json`.

- 2026-10-17: T0 platform retarget implemented (port 8080, spec error envelope, `001_init.sql`, baseline seed, `/health`, `/audit/v1/reset`). `Dockerfile` takes `ARG NODE_IMAGE` (default `node:22-alpine`) so a machine without Docker Hub access can build from a local image. Test helper `assert_error` in `tests/api/conftest.py` now checks the `{error:{code,message,details}}` envelope. - 2026-10-17: Swiss rounds >= 2 use an exact branch-and-bound pairing (`domain/fixtures/pairing.js`: admissible score-order lower bound, infeasible-state memo, early stop at the bound) instead of the planned weighted blossom (ADR-014). Verified optimal against brute force for n <= 10 and by tournament simulation up to n = 64; worst-case time is not polynomial, accepted for Phase I limits. `domain/fixtures/index.js` also owns request validation for API-04.
- 2026-10-17: Checkout runs in ONE transaction (order-id advisory lock → variants `FOR UPDATE` in variant_id order → stock check → pure gateway decision → decrement + order + outbox + replay record, or ROLLBACK as the release) instead of the two-phase reservation in ARCHITECTURE §6.3. Same guarantees (no oversell, stock/reserved consistent, released stock purchasable, same-id requests serialized), no crash-orphaned reservations; `variants.reserved` stays 0 and the `reservations` table plus sweeper are unused for now. Failed payments are recorded (payment_attempts + `order.payment_failed`) in a separate small transaction after the rollback.
- 2026-10-17: Receipt PDF is generated by hand (`pdf/receiptPdf.js`, uncompressed, literal text, Helvetica) so no `pdfkit` dependency is added and any extractor or byte search finds the order id and `PKR 4500.00`. pypdf added to tests/requirements.txt for the extraction test.
